# Design specification v3 (final): implementation brief

Status: approved by the owner, 2026-10-12. This file supersedes the visual parts of `DESIGN_SPEC.md` (v1) and all of `DESIGN_SPEC_V2.md`. Behaviour rules in v1 (URL state, keyboard model, live regions, states, API use) still apply unless this file changes them. The visual source of truth is `docs/design-system/` (open the `.html` files in a browser; `tokens.css` holds every value; previews in `docs/design-system/previews/v3/*.webp`).

## 1. Principles (non-negotiable)
1. Navy `#000055` is ink: the one primary action per view, selection, focus ring, the single highlighted series. Under 5% of any screen. Dark mode uses `#b4b4ec` for ring/links/selection and an ink-coloured primary button (`#ecedf2` fill, navy text).
2. Hairline borders define surfaces; no resting shadows. Shadows only on floating layers (menus, dialogs, popovers, the screenshot frame).
3. Hierarchy by weight and grey: `--ink`, `--ink-2`, `--ink-3`; weights 400/500/600. No colour for emphasis.
4. Status is a coloured shape plus an ink word; never colour alone. Shapes (12 px): critical diamond, serious triangle, minor square, needs review ring with dot, no issue found outline tick, could not decide dashed ring, audit failed filled circle with x, running arc, complete plain tick, alert filled circle with !. Zero counts are drawn hollow at 45% opacity with ink-3 text.
5. Honest by default: "No issue found" (never "passed"); "Could not decide"; every report shows "This tool checks 8 of the 86 WCAG 2.2 success criteria" and links "What this result does not mean"; a fix is "Mark as fixed" and stays "Fix not verified" until a later audit no longer finds it; the verdict sentence counts failures, needs-review findings and undecided criteria separately; levels (A/AA/AAA) shown on every criterion; severity is impact, not conformance.
6. Plain language: sentence case, verbs on buttons, no exclamation marks, numbers with units, tabular figures (`font-variant-numeric: tabular-nums slashed-zero`). Ratios render as number in ink + `:1` in ink-3.
7. Accessibility of the tool itself: WCAG 2.2 AA everywhere, focus ring 2 px with 2 px offset, targets at least 24 px (measured in px), forced-colors block, reduced motion, reflow to 320 px, landmarks and headings per screen, one persistent polite status region per screen, focus to the page h1 on route change, all existing keyboard and focus behaviour preserved (see the a11y pass in commit a2ff513).

## 2. Tokens and type
Exactly `docs/design-system/tokens.css` (light and dark), ported to Tailwind v4 theme variables in `apps/web/src/app/globals.css`. Fonts: Figtree (UI) and Geist Mono (data), bundled locally with `next/font/local` from `apps/web/src/fonts/` (copy `docs/design-system/fonts/*.woff2`); no CDN. Root font size 16 px (rem-based type: 24/32 page title 600, 16/24 section 600, 14/20 body, 13/18 dense, 12/16 label 500). Radii 4/6/8. Spacing 4/8/12/16/24/32. Controls 32 px default, 28 small, 40 large/forms.

## 3. Shell
Left sidebar 248 px (white surface, hairline right border): brand row 56 px aligned with the 56 px top bar; primary "New audit" button; nav Overview, Audits, Review queue (count of waiting items), Sites; "Research": Evaluation, Study; "Recent sites" (3, separate `nav` landmark); bottom: Settings, Help and method; user block. Active item: tint background + 2 px navy bar inside the item. At <=1100 px the sidebar collapses to a 64 px icon rail; at <=720 px it becomes a top bar with a menu button opening a modal drawer (focus trapped, Esc closes, focus returns). Top bar: breadcrumbs (`nav aria-label="Breadcrumb"`), page actions, search button opening the command palette (Base UI Dialog + Combobox, no `cmdk`; Ctrl K on non-Mac), theme toggle (sun/moon, `aria-pressed`, constant name).

## 5. Backend additions (services/app)
- Findings decisions: migration 0004 adds `decision_reason`, `decision_note`, `decided_at`, `decided_by` to `findings`; `status` values `open | fixed | dismissed | confirmed | unsure` (map existing `ignored` to `dismissed` in the migration). `PATCH /findings/{id}` accepts `{status, reason?, note?}`; dismissing needs a reason; returns the finding with decision fields.
- `GET /review?state=waiting|decided|all&site=&sc=&reason=` returns needs-review findings of each site's latest finished run with run id, url, viewport, sc, element, evidence rows, `needs_review_reason`, crop availability, age; plus counts per reason.
- `GET /sites` returns one row per site (host + path of the URL, or the folder/upload label) with latest run summary, previous run id, failure counts and change since the previous finished run of the same source and viewport, to-review count, criteria decided on the latest run, and status/time.
- `GET /runs/{id}/delta` compares with the previous finished run of the same source and viewport: `fixed`, `new`, `still_present` (match on sc + element, then bbox IoU at the protocol threshold, focus findings on focus_index), and `fixes_verified` (findings marked fixed in the previous run that are gone now).
- `GET /summary/week` returns audits run this week and last week, fixes verified, review decisions, median criteria decided, running audits, and fixes to verify (findings marked fixed whose site has not been audited since).
- All with tests in `services/app/tests/`; regenerate `apps/web/src/api/types.ts` with `pnpm -C apps/web gen:types` (never hand-edit it).

`make check` green; `pnpm -C apps/web build`; full Playwright suite including the axe gate on every route and state in light and dark at 1440 and 390 px; focus assertions; visual comparison against the mock-ups; no console errors; no horizontal scroll at 320 px except data tables and the stage.
