# Check catalogue (RO1), v1

For each in-scope WCAG 2.2 success criterion: what the auditor measures, from which input, with which rule, and how reliable the verdict is. Thresholds are the Protocol v1.1 values and live in `protocol.yaml`; this table is their documentation. ACT = W3C Accessibility Conformance Testing rule id where one exists.

| SC | Level | Unit | Inputs needed | Decision procedure (summary) | Threshold / rule | Detectability | Tier when input present | ACT / axe |
|---|---|---|---|---|---|---|---|---|
| 1.4.3 Contrast (Minimum) | AA | text run (line box) | screenshot + DOM (or OCR) | foreground vs background behind glyph mask; worst 24-px window on non-uniform backgrounds | 4.5:1; large text 3:1 (≥ 24 px, or ≥ 18.66 px at weight ≥ 700, O8); exempt logotype, disabled, placeholder, incidental | **both** (rule: axe `color-contrast`; pixel: module) | automated with DOM; needs-review when size/weight unknown | ACT `afw4f7`; axe `color-contrast` |
| 1.4.11 Non-text Contrast | AA | control / graphic | screenshot + DOM | boundary ring vs inside and outside, best of border/fill; state contrast for checked/selected; skip when a visible text label identifies the control | 3:1; O2 (icon-only links), O6 (slider handle identifies control); exempt disabled and unstyled native controls | **pixel** | automated for icon/border controls; needs-review for graphics | none in axe-core |
| 2.4.7 Focus Visible | AA | focus stop | focused/unfocused pair | changed-pixel mask within element rect + pad; max state contrast | visible if ≥ 1.5:1 change (R1, protocol threshold); unsettled flag if > 5 % change outside the pad (R2) | **pixel** | automated | none in axe-core |
| 2.4.11 Focus Not Obscured (Minimum) | AA | focus stop | pair + DOM fixed/sticky regions | fraction of the focused rect covered by opaque author content | entirely covered → fail; open modals and dismissible content exempt (R6) | **pixel** (+DOM) | automated with DOM; needs-review pixel-only | none |
| 2.4.12 Focus Not Obscured (Enhanced) | AAA | focus stop | same | any part covered → fail | partial or entire (R6) | **pixel** (+DOM) | as above | none |
| 2.4.13 Focus Appearance | AAA | focus stop | pair | added-indicator mask; ring detection; thickness; change contrast | R5: solid ring ≥ 2 CSS px at ≥ 3:1 change all sides → meets; else O4: changed pixels at ≥ 3:1 ≥ 4(w+h); unstyled default ring exempt; no visible indicator → n/a (R1) | **pixel** | automated | none |
| 2.5.7 Dragging Movements | AA | drag widget | DOM | native range input → pass; custom slider/drag widget without a visible single-pointer alternative → fail | O7 severity critical; "essential" exception → needs-review | **DOM** | automated with DOM; not-assessable without | none |
| 2.5.8 Target Size (Minimum) | AA | target | DOM (or detector) | bounding rect < 24 px in either dimension, then exceptions: inline (prose line box), spacing (24-px circle intersects no other target), equivalent, user-agent, essential | 24 × 24 CSS px; O3 | **both** (rule: axe `target-size`; pixel/DOM: module) | automated with DOM; needs-review detector-only | axe `target-size` |

Coverage claim (RQ3): the rule-only configuration returns a verdict on **2 of 8** criteria; the hybrid configuration on **8 of 8** with DOM, **5 of 8** screenshot-only (1.4.3 needs-review, 1.4.11, 2.4.7, 2.4.11/12, 2.4.13, 2.5.8 needs-review; 2.5.7 not-assessable).

Divergences from the normative text, stated for the thesis: 2.4.7 has no numeric threshold in WCAG (R1 is a protocol operationalisation); 2.4.13's 3:1 is a change-of-contrast per pixel (O4), with R5 as the practical rule for complete rings; 2.5.8's inline exception is restricted to prose line boxes (stricter than O3's calibration reading, see DECISIONS ADR-004).
