## ADR-012 Real-stratum element geometry comes from pixels, not the re-rendered DOM (2026-10-10, planner)
Context: M3 found that `dom.html` re-rendered offline does not reproduce real pages' layout (external CSS missing; live `<base href>` also failed because sites have drifted): 0 of 15 focus rects matched a DOM box on both real fixtures. The benchmark captures stored no element geometry at capture time (`proxy_findings.json` has selectors and colours but no rects). Synthetic pages are self-contained and re-render exactly.
Options: (a) re-capture the real pages with geometry (rejected: live pages have changed since the ground truth was labelled); (b) pixel element source for the real stratum (detector boxes + OCR text lines); (c) drop page-level SCs on the real stratum (rejected: guts RQ2).
Decision: per-capture element source selection.
- **Focus SCs (2.4.7, 2.4.11, 2.4.12, 2.4.13), all strata:** use the capture-time focus rects in `meta.json` plus the focus PNGs. Unaffected by this problem.
- **Page SCs on synthetic pages:** `DomElementSource` (exact).
- **Page SCs on real benchmark pages:** `PixelElementSource` = OCR text lines (RapidOCR detection, promoted from stretch to core) for 1.4.3 + RF-DETR detector boxes (M10) for 1.4.11 and 2.5.8. 2.5.7 uses DOM *structure* (role=slider, input[type=range], drag libraries) for presence, located on the screenshot via the detector or marked `needs-review` without a box.
- **New captures made by the app (live mode):** M1b adds capture-time geometry (`elements.json`, from `extract.js` run on the live page at capture time), so `DomElementSource` is exact for everything the app captures from now on.
Evidence: M3 NOTES. Consequences: the detector moves back onto the critical path for the real stratum (M10 runs before M6); this matches the thesis title (a screenshot-based auditor) and makes the DOM-vs-pixel ablation (ADR-002) a real-vs-synthetic contrast to discuss in Chapter 5. The rule-only baseline is unaffected (it ran on the same snapshot DOM).

## ADR-013 Page-SC matching allows containment for block-level truth (2026-10-10, planner)
Context: synthetic 1.4.3 truth boxes are whole text blocks (e.g. 640×60) while text findings are line boxes (437×16, IoU 0.18). Real ground truth follows R3 (one box per text run), so the mismatch is synthetic-only, but the rule must be one rule.
Decision: a page-SC finding matches a truth box if IoU ≥ `thresholds.iou_match` **or** the finding lies ≥ `thresholds.containment` (0.5) of its own area inside the truth box. Several findings matched to the same truth box count as **one TP**; the extras are **merged duplicates**, not FPs (reported separately as `duplicates` in metrics.json). A truth box with no match is one FN. Applies to 1.4.3, 1.4.11, 2.5.7, 2.5.8 in all strata. The IoU sensitivity sweep (M8) reports both the IoU-only and the IoU-or-containment rule so the choice is visible in Chapter 5.

## ADR-014 Evaluation harness scoring policy (2026-10-10, M2)
Context: PLAN §8 fixes the units but leaves several scoring choices open.
Decisions:
- **Rule-only counts axe `violations` only.** `incomplete` (needs-review) findings are excluded by default (`--include-needs-review` adds them), matching the benchmark baseline (`run_baseline.py` reports violations as the headline). 862 needs-review nodes are excluded on the full benchmark and reported in `metrics.json` (`rule_findings_dropped`). When the hybrid condition exists, both conditions must use the same tier policy (automated only by default, needs-review-included as a reported variant), otherwise ΔPrecision compares different policies.
- **Units.** Page SCs: (page x viewport, SC) with ADR-013 matching; focus SCs: (stop, SC). Real: all eight SCs, `excluded_focus_stops` skipped, R6 `not-assessable` removes 2.4.7/2.4.13 from that stop's units, R1 `na` counts as a negative (as `agreement.py`). Synthetic: desktop only, seeded SC only (2.4.11 pages also 2.4.12). Synthetic focus truth has no per-stop labels, so a stop is positive when its rect (rect + scroll) matches an annotated element's rendered rect (protocol IoU or containment); this is a derivation, not ground truth.
- **Counting.** A truth box is found if any finding matches it; a finding matching nothing is a FP; extra findings on an already-found box are `duplicates`, not FPs. Page units carry TN = 1 only when there is neither truth nor finding; `correct` (for McNemar) is `fp == 0 and fn == 0` for page units, truth == prediction for stops.
- **Statistics.** Cluster bootstrap over pages (10,000, seeded). ΔPrecision (hybrid minus rule-only) uses the same resamples; the H1 non-inferiority margin -0.05 is PLAN §8's study hypothesis, kept as a constant in `eval/bootstrap.py` and echoed in `metrics.json`, not a Protocol value. Where precision is undefined in a resample (a condition makes no predictions, e.g. rule-only on six SCs) the resample is dropped and `n_valid` reported: ΔP is then not estimable and must not be read as non-inferior. McNemar is exact and compares hybrid (A) with rule_only (B), chosen by name (`mcnemar_pair`, ADR-025; before 2026-10-10 it paired the first two listed conditions); Benjamini-Hochberg is applied over the SCs within each stratum (family of eight).
- **Coverage (RQ3)** for rule-only is the static set of SCs axe has rules for (1.4.3, 2.5.8), not a measured count.
Consequences: Chapter 5 must state these policies; the hybrid condition (M6) must adopt the same tier policy.

## ADR-016 Static-module rulings beyond the Protocol text (2026-10-10, M4)
Context: Protocol v1.1 fixes thresholds and severity for contrast but leaves gaps the modules must fill.
Decisions:
- **1.4.3 severity** follows amendment C exactly (serious below 4.0, or 2.7 for large text; otherwise minor). Large text per O8 from DOM `font_size_px`/`font_weight`; with no DOM style the module uses 4.5 and tier `needs-review`.
- **1.4.11 severity is always `serious`.** Amendment C defines a narrow-failure (minor) band only for text contrast; an earlier version reused the 2.7 large-text cutoff for non-text, which the review rejected as invented. Consequence: the synthetic truth labels boundary cases (2.9:1) as minor and the module says serious; severity is not part of the matching or the M4 acceptance.
- **1.4.11 scope.** Evaluated: text inputs and choices (boundary ring: outermost or next-inner 1-px ring versus the pixels 2 px outside, or the fill, whichever contrasts more; ring geometry in `protocol.yaml` `heuristics`). Exempt: disabled, unstyled native controls, buttons and links with a visible text label. O2: icon-only buttons and links are measured from pixels and reported as `needs-review` (stroke anti-aliasing makes the estimate optimistic). O6: sliders are not evaluated (handle contrast is not measured). Not implemented: state contrast for checked or selected controls, and non-interactive graphics.
- **2.5.8** uses the 24-px circle rule of `validate_captures.py` (strict `<`, so touching circles pass, O3). A target nested in another is not its neighbour; disabled neighbours still count; zero-size boxes are ignored. The inline exception is an operationalisation: a link whose line shares a text run of the same parent (vertical overlap at least half the link height, horizontal gap at most half the target size). A separator character in a nav row can therefore exempt links the WCAG reading would not (a possible small precision cost, see ADR-004). "Equivalent" and "essential" are recorded as not modelled. Severity is `serious`; the protocol's `primary-undersized-no-spacing` (critical) needs a primary-control signal the DOM does not give, so critical is not emitted.
- **1.4.3 exceptions** implemented: disabled, text inside `svg` (logotype/graphic). Placeholder text is not a text node so it never reaches the module. Incidental text is not modelled. Effective opacity (product over ancestors) is applied to the text colour.
Consequences: Chapter 4 must list these; the M6 hybrid condition inherits the tier policy of ADR-014 (automated only by default).

## ADR-017 Focus-criterion modules: rulings beyond the Protocol text (2026-10-10, M5)
Context: M5 measures 2.4.7, 2.4.11, 2.4.12, 2.4.13 from the focused/unfocused PNG pair of each stop (all strata) and 2.5.7 from DOM structure.
Decisions:
- **Visibility (R1, 2.4.7)** uses the strongest state contrast among the *added* pixels (PLAN §4.3 "max state contrast"); a first version used the median and was replaced because a large faint fill change masked a crisp border. Added pixels are changed pixels (sum of channel differences above the delta) whose focused colour is farther from the page background (sampled from the pad frame around the element) than the unfocused colour, so removed pixels never count (R4). The median is kept as evidence.
- **2.4.13** runs R1 (not visible: not applicable), then the UA-default-ring exemption, then R5 (complete solid ring of `ring_min_px` at `ring_min_contrast` on every side, judged over each side's central half so rounded corners never decide it; a side whose pad band meets the view edge and shows no indicator counts as clipped, O1, only when the other sides are complete), then O4 (strong added area >= 4(w+h) in CSS px). Severity `minor` (amendment C).
- **Unstyled default ring (OPEN QUESTION for the researcher).** The M5 prompt and CHECK_CATALOGUE say an unstyled default ring meets. The labelling Protocol §5.6 has no such exemption (its only default-outline wording is for 2.4.7, "browser default outline preserved: passes", and the ambiguity table). The sealed ground truth evidently applied the area/contrast test to many default rings. The module follows the M5 prompt: it recognises Chromium 153's ring by colour (`ua_focus_ring_rgb`, `ua_ring_min_share`) and exempts it; `ua_default_ring_exempt: false` evaluates it instead (run with `AUDITOR_PROTOCOL=<file>`). Measured on the real stratum: exempt P 0.747 / R 0.397 (TP 148, FP 50, FN 225); evaluate P 0.715 / R 0.879 (TP 328, FP 131, FN 45). Synthetic is unaffected (perfect both ways). The default is the prompt's reading; M8 should report both.
- **2.4.11 / 2.4.12 (R6)** with element geometry: a 5x5 grid of points on the focused rect against opaque (alpha 1) fixed regions in viewport coordinates, and sticky regions only at scroll 0; a region that lists the focused control among its descendants (`contains_refs`) is not an obscurer. Entire coverage (2.4.11 and 2.4.12) also requires that nothing changes inside the rect; partial coverage fails 2.4.12 only. Without geometry (the benchmark's real pages) only 2.4.11 is reported, from "no pixel change inside the rect", tier `needs-review` (a stop with no indicator at all looks the same, so it is excluded by the default policy). Known gaps: sticky regions are not tracked after scrolling, translucent children of an opaque region are missed, severity is `serious` for both (the protocol has no rule), and a covered stop is not marked not-assessable for 2.4.7/2.4.13 when there is no geometry (scoring is unaffected: those truth units are skipped).
- **2.4.7 severity** is `serious`: the protocol's critical rule needs a primary/secondary control signal the DOM does not give. `unsettled` stops (more than `focus_unsettled_fraction` of the pixels outside the pad changed, R2) become `needs-review`.
- **2.5.7** passes native range inputs; a custom `role=slider` fails (critical, O7) when none of its nearest `slider_widget_depth` ancestors contains a button, input, select, textarea, link or `role=button/spinbutton`. Without DOM structure nothing is reported. Drag libraries and "essential" are not modelled.
- New `protocol.yaml` heuristics: `focus_pad_px` (6, the annotators' fdiff pad), `ring_side_margin_fraction`, `slider_widget_depth`, `ua_focus_ring_rgb`, `ua_ring_min_share`, `ua_default_ring_exempt`.

## ADR-021 Fusion semantics (2026-10-10, M6)
Context: PLAN §1.4 asks for one finding per element with provenance `rule | pixel | both`. The first implementation put every same-criterion finding whose boxes overlapped (IoU, or containment either way) into one connected component. On the sealed benchmark that made hybrid *worse* than rule-only on real-stratum 1.4.3 (TP 621 vs 653): chains of nested axe elements collapsed into a single finding.
Decision: a rule finding **is** the element. Pixel findings of the same criterion that overlap it (IoU >= `iou`, or containment >= `containment` either way; `protocol.yaml`) join the smallest overlapping rule element, so the fused finding has provenance `both`, the rule element's box, the worst member severity, the most decisive member tier (a rule violation plus a needs-review pixel finding is `automated`; agreement is evidence), the best member score, and both channels' evidence (`evidence.rule`, `evidence.pixel`, member counts). Same-channel duplicates merge only when each box lies at least `containment` inside the other, so a child element inside a larger parent stays a separate finding. Focus findings are one element per (criterion, focus stop). Pixel findings with no rule element stay `pixel`; rule findings with no pixel counterpart stay `rule`. Ids `f001...` are assigned after a deterministic sort by criterion, stop and position. Result on the benchmark: real 1.4.3 hybrid TP 663 / FP 272 against rule-only TP 653 / FP 249.
Consequences: fusion only adds evidence and pixel-only detections to rule elements; it never removes a rule finding.

## ADR-022 Coverage verdicts and the hybrid condition (2026-10-10, M6)
A criterion's verdict class per channel is decided from the inputs, before any finding: rule channel `automated` for 1.4.3 and 2.5.8 when axe ran, else `none`; pixel channel `automated` when the measurement is decisive (DOM or stored element geometry for 1.4.3 text style, 1.4.11, 2.5.7, 2.5.8; focus images for 2.4.7 and 2.4.13; geometry as well for 2.4.11/2.4.12), `needs-review` when it rests on OCR or detector boxes (1.4.3 from OCR, 2.4.11 from the pixel fallback, 1.4.11 and 2.5.8 from detector boxes), `not-assessable` when the criterion has no input. Hybrid = the most decisive of the two. "Reliable" counts `automated` verdicts; the report also gives the count including needs-review. Measured: rule-only 2 of 8; hybrid on self-contained synthetic pages 8 of 8; hybrid on the benchmark's real pages (no element geometry, ADR-012; OCR; no detector yet) 4 automated, 5 with needs-review. The M6 acceptance target "hybrid >= 6 on the real fixtures" assumed DOM geometry for them and is **not met** on the real fixtures; it needs the detector (1.4.11 and 2.5.8 become needs-review, giving 7 with a verdict).
The evaluation harness gains the `hybrid` condition: rule findings (boxed, non-empty) plus pixel findings, fused, then the ADR-014 tier policy (automated only by default; `--include-needs-review` for the variant), so rule-only, pixel and hybrid are scored identically.

### ADR-021 / ADR-022 amendments (2026-10-10, M6 review)
- **Provenance and severity.** `both` when the group holds a rule and a pixel member. The bbox of a fused finding is the rule element's box (the rule finding is the element); a pixel-only group gets the union of its boxes. The severity comes from the pixel member when there is one (it carries the measured value and the Protocol severity rule); a rule-only group keeps axe's mapping. Tier is the best tier of any member (ADR-014's policy then filters), score the highest. Evidence is always nested: `{"members": {rule, pixel}, "rule": ..., "pixel": ...}`.
- **Tier promotion.** A needs-review pixel member joined to an automated rule member yields an automated finding; the pixel member's measurement stays in the evidence. This can raise hybrid precision above or below rule-only; the measured effect is in NOTES (M6).
- **Coverage counts.** CHECK_CATALOGUE counts six criteria as reliable with a detector and no DOM geometry; without a detector the OCR-only source gives four automated and five with any verdict (the benchmark's real pages). The acceptance figure of six is therefore not reachable until M10 ships a model or captures carry `elements.json`; the pinned test asserts 4 / 5 (ADR-012).
- **Shared browser.** The rule runner, the DOM element source and the PDF export now share one Playwright driver (`auditor/browser.py`, reference counted). Two `sync_playwright()` starts in one thread raise, which silently dropped two synthetic items from the first hybrid evaluation (`items_failed`).

## ADR-023 Web shell: API proxy, run execution and form-control contrast (2026-10-10, M7a)
Context: M7a needs the browser to reach the FastAPI service, run progress without Celery or Redis (CLAUDE.md), and a form that passes the app's own 1.4.11.
Decisions:
- **Same-origin proxy.** A Next route handler (`app/api/[...path]`) forwards to `API_URL` at request time, streams bodies (SSE, multipart) and drops `cookie`/`host`. Rewrites were rejected because they are fixed at build time, which breaks the e2e setup that picks its own API port.
- **One `auditor audit` subprocess per run.** The service queues a subprocess (in-process runner, one job at a time) that writes `events.jsonl` (one JSON event per stage, per viewport) and `summary.json`; SSE tails the file and ends on the terminal status. Cancel kills the process group; a timeout (default 900 s) does the same. Cancel and timeout use out-of-band return codes (1001, 1002) so a real SIGKILL is not mislabelled. Runs left queued or running by a previous process are failed on startup.
- **Folder source is allow-listed** (`FOLDER_ROOTS`, default `fixtures/`) so the API cannot read arbitrary paths; uploads are re-encoded to PNG, capped at 25 MB and 60 Mpx, one image per viewport (width <= 600 is mobile). Screenshot-only runs have no DOM, so the rule channel is skipped (`stage_status.rules = skipped`) and `rule_only` is rejected for them.
- **Input border token.** `--input` is `#71717a` (light) and `#8b8b94` (dark), not zinc-200/zinc-800: a field boundary at 1.2:1 fails 1.4.11. This departs from the DESIGN_SPEC section 1 border token for form controls only.
- Type scale and radii remapped so shadcn's `text-sm` is 13/20 and radii are 4/6/8/10 px as specified.

## ADR-024 Report screen: data flow, ordering and overlay semantics (2026-10-10, M7b)
Context: the report needs per-finding status that survives reloads, a canvas that is fully keyboard-operable, and zero axe violations in every layout.
Decisions:
- **Findings live in SQLite as well as report.json.** When a run finishes, `ingest_run` copies each viewport's report into captures/findings/coverage (migration 0002 adds `findings.key`, the report's `f001`-style id). Statuses are keyed by (viewport, key) and survive a re-ingest; if the finish hook missed a run, the first read ingests lazily. Guidance, evidence rows and crops stay in report.json and are merged into `FindingOut`, so the UI types are generated from OpenAPI (nothing hand-written).
- **Two orders.** Arrow keys on the canvas follow reading order (top to bottom, left to right) because that is what a sighted keyboard user expects; J/K and the table follow criterion, then severity, then position, because that is the order the rail and table show. The e2e test pins both and asserts they differ on the fixture.
- **Overlay painting.** Boxes are painted largest first so the smallest is on top and clickable; the DOM order is therefore by area, while the roving tab stop and arrow navigation use reading order. Dimming of unselected boxes applies to the shapes only: dimming the text label dropped its contrast below 4.5:1.
- **Focus pair.** Diff is computed in the browser from the two viewport PNGs (changed pixels red on grey, threshold 8/255); it is a viewing aid, not a measurement. The pair view replaces the page canvas because focus PNGs are viewport images scaled by `png_scale`, not page coordinates.
- **Exports.** JSON, HTML, PDF (page count from pypdf) and CSV; CSV cells that start with `=`, `+`, `-`, `@`, tab or CR are prefixed with a quote against spreadsheet formula injection.
- **Layout.** Three resizable panes from 1280 px (DESIGN_SPEC says 1440; 1280 keeps the panes usable on common laptops), a Sheet for the detail pane from 1024 to 1279 px, tabs below 1024 px. Separators are keyboard operable and have a 24 px hit area.
- **Lint.** `src/components/report` switches off biome's `useSemanticElements`, `noNoninteractiveTabindex`, `noStaticElementInteractions` and `useAnchorContent`: the overlay uses `<g role="button">`, scroll regions must be focusable (axe `scrollable-region-focusable`), and menu items render their own anchor content.

## ADR-025 Evaluation screen, compare data and the H1 test pair (2026-10-10, M7c)
- **H1 pair.** The paired test is hybrid against rule_only chosen by name, whatever order `--conditions` lists them (the harness had used list position; see the correction in NOTES M7c and FAILED_ATTEMPTS). With other condition sets the first two are compared.
- **Eval data path.** `auditor eval` writes `metrics.json`; the service stores it in `eval_runs` and serves a typed view (cells with CIs, McNemar rows, ΔPrecision rows, run metadata). Results can also be imported from directories named in `EVAL_IMPORT_DIRS` (the repo's `eval/fixtures` for the e2e). One evaluation runs at a time; progress is a `{done,total}` JSON line per capture in `progress.jsonl`, streamed over SSE.
- **Compare.** A hybrid run also writes `rule_only.json`: the same axe findings fused without the pixel channel, so no second capture or axe pass is needed. Pairing of hybrid and rule-only findings uses the Protocol match thresholds on the server (IoU or containment for page findings, the focus stop for focus findings); the client never holds thresholds.
- **Chart.** Recharts bars (precision, recall, F1) with 95% bootstrap whiskers, wrapped in a `role="img"` element whose label states every value; a table alternative is one toggle away and carries the intervals as text.

## ADR-026 Final evaluation outputs, figures and the stability check (2026-10-10, M8)
- **No threshold or tie-break changed.** M8 re-runs the frozen pipeline; every number comes from the same `protocol.yaml` (sha e8c35965...) and seed.
- **Figures are vector and deterministic.** SVG and PDF (matplotlib `svg.hashsalt`, no creation date), because PNG figures over 200 KB are not committed and the thesis needs vector output. `make eval` regenerates them after the evaluation.
- **IoU sweep reading.** The sweep reports both matching rules; the containment rule (ADR-013) is what makes results stable above IoU 0.5, so the headline figures keep the Protocol thresholds (IoU 0.3 or containment 0.5) and the sweep is evidence, not a retune.
- **Stability check design.** A seeded sample of 10 real desktop pages is re-captured live and run through the same hybrid pipeline as the benchmark capture; findings are matched one-to-one per criterion with the Protocol thresholds (focus criteria by stop index) and agreement is the Dice coefficient. It is a sanity check on capture drift plus element-source differences, not a re-labelling. The artefact is not reproducible by design (live pages): it records its run time, versions and `reproducible: false`, and `make stability` regenerates it. Seeds come from one constant (`DEFAULT_SEED`).
- **Shared Playwright driver in the capture path.** `PlaywrightBrowser` now acquires the process-wide driver (`auditor/browser.py`, ADR-023/M6) instead of starting its own: capturing and then running axe in one process raised "Playwright Sync API inside the asyncio loop" and failed all ten pages in the first stability attempt.

## ADR-027 Confidence calibration: measured, not applied (2026-10-10, M11)
Context: `Finding.score` is a tier-and-measurement score, not a probability; the thesis claims scores can be read as confidence only if checked.
Decision: measure reliability (ECE, Brier, tier accuracy) against ground truth for the pixel and hybrid conditions on both strata and publish it with the evaluation; do not rescale scores. Evidence: `eval/2026-10-10/calibration.md`.
